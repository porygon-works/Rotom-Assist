# 質問の記録の定期見直し（手順書）

定期タスクが毎回この手順で動く。目的は 2 つ。

1. **答えの精度を上げる**: 答えられなかった・間違えた質問の原因を直す
2. **AI に頼らずに答えられる質問を増やす**: AI に回った質問の傾向を見て、確実に読める言い方はルール（`lib/rules.ts`）で即答する。AI は遅く（数秒）、無料枠の上限で止まることもあるため

## 0. 守ること

- 計算は必ず @smogon/calc。数値を手で直さない
- ルールは「確実に分かるときだけ答える」。**即答で誤り 0 件**を崩す変更は入れない（迷ったら AI に回すままにする）
- 名前の補正は AI にさせない（構成設計 A6）。聞き間違いは `data/aliases.json`・`data/readings.json`・`lib/resolve.ts` で直す
- 記録には質問文が入っている。質問文をリポジトリに書くのは回帰テスト（`eval/cases-log.ts`）と下の履歴だけにし、端末 ID は書かない
- 適用済みの SQL（`supabase/`）は書き換えない。API キーや個人情報をリポジトリに書かない
- 実装を変えたら設計書（`docs/architecture.md`）も直す

## 1. 集計

```
npm ci
npx tsx eval/ask-log.ts
```

前回の続き（`eval/ask-log-state.json` の `lastId` より後）を集計する。新しい記録が 0 件なら、何もせずに終える（コミットしない）。

集計の見方:

| 節 | 見ること |
|---|---|
| 1. 答えられなかった | 名前が分からない／聞き返した／AI が混んでいた。原因ごとに直す |
| 2. 聞き返し | 本当に情報が足りなかったのか、読み落としたのか |
| 3. AI に回った質問 | 「今はルールで即答」のうち **AI と違う解釈** はどちらかが誤り。必ず調べる。「まだ AI が要る質問」は intent ごとの傾向を見る |
| 4. 遅かった | AI の待ち。ルールで受けられないか |
| 5. AI の失敗 | 上限（429）・時間切れが多い候補。設定の見直しが要るなら報告だけする（キーや候補の順番は勝手に変えない） |
| 6. 繰り返し | 同じ質問を何度も言い直している ＝ 答えが合っていなかった可能性 |
| 7. 聞き取りの経過 | 画面が送る聞き取りの記録（roas.history の kind=event）。`mic-end timeout`（終わりの知らせが来ない）・`mic-stale`・`mic-error` が多い端末は、音声認識が止まっている。**声を拾わないのが一番まずい**ので、増えていたら最優先で報告する（音の鳴らし方など画面側の変更が原因のことが多い） |

答えの中身（読み上げ文・計算条件）が質問と合っているかも見る。例: 「HB特化」と言ったのに性格が B↑ になっていない、天候を言ったのに入っていない。

## 2. 直し方（原因ごと）

| 原因 | 直す場所 |
|---|---|
| 名前の聞き間違い・漢字の書き起こし | `data/aliases.json`（あだ名・決まった聞き間違い）、`data/readings.json`（漢字の読み）。仕組みで直るものは `lib/resolve.ts` の読みの比較 |
| ルールで読めない言い回し | `lib/rules.ts` の辞書の言い回し（`w`）・決まった形（`pattern`）。意味のある語（条件）を黙って捨てない |
| AI の解釈の誤り | まずルールで受けられないか考える。指示文（`lib/extractPrompt.ts`）を変えるのは最後の手段（変えたら eval-plan の測り直しが要る） |
| 回答文・表示 | `lib/answer.ts`、`lib/ask.ts`、`lib/card.ts` |
| 計算の誤り | `lib/battle.ts`。計算ライブラリの対応範囲を確かめる |

直した質問は、**直す前に** `eval/cases-log.ts` に回帰テストとして足す（id は ask_log の id。正解は「その質問で本当に聞きたかったこと」を書き、ルールの出力に合わせて書かない）。

## 3. 確かめ（全部通ったときだけコミット）

```
npx vitest run            # 単体テスト（全ポケモンの取り違えテストを含む）
npx tsc --noEmit
npx tsx eval/rules.ts     # 即答で誤り 0 件であること（cases + cases2 + cases-log）
npx tsx eval/rules.ts fresh
npx tsx eval/replay.ts    # 保存済みの AI 出力 566 件。変更の前後で回答文の差を見て、意図しない変化がないこと
```

## 4. 記録と報告

1. `npx tsx eval/ask-log.ts --mark` で、見た最後の id を `eval/ask-log-state.json` に書く
2. 下の「履歴」に 1 行足す（日付・見た件数・直したこと・即答の割合）
3. コミットして push
4. 最後に短く報告する: 見た件数、答えられなかった件数とその原因、直したこと、ルールで即答できる割合（前回から）、人に決めてほしいこと
