# AI 比較テスト計画（②理解する：質問の中身の取り出し）

- 状態: 計画（未実施）
- 目的: [requirements.md](requirements.md) 5.2 の AI 候補から、「質問の中身の取り出し」に使うものを決める（雑談は後回しのため、今回は対象外）
- 進め方: 本書に合意 → テスト用の小さなスクリプトを作る（**作る前に確認する**）→ 実施 → 結果を本書の 7 章に記録

## 1. 比較する候補
| # | 候補 | 用途 | 費用 | 必要なもの |
|---|---|---|---|---|
| 1 | Gemma（Gemini API 無料枠） | 取り出し | 0円 | Gemini API キー（無料、カード不要） |
| 2 | Gemini Flash（無料枠） | 取り出し | 0円 | 同上 |
| 3 | Gemini Flash（AI Pro のクレジットで有料利用） | 取り出し | 0円（月 $10 まで） | Cloud Billing の設定、クレジットの有効化 |
| 4 | Groq（gpt-oss など、無料枠） | 取り出し | 0円 | Groq API キー（無料） |

- Claude Haiku は試さない（要件 Q5）

- 実施時点で各社の公式ページを見て、モデル名・上限・単価を記録する（条件が変わりやすいため）
- #2 と #3 はモデルが同じなので、精度は 1 回の測定で兼ねる。違いは上限・速さ・データの扱いだけを見る

## 2. テストの考え方
- **取り出しテスト**: AI に「質問の中身」を決まった形（JSON）で返させ、正解と比べる。数値の計算はさせない
- 雑談の返事の質は測らない（雑談は後回し）。雑談の質問（#21〜#23）は、`chat` と**判別できるか**だけを見る
- ロトムの口調はテンプレートで出すので、AI の口調は測らない
- **連続テスト**: 1 分間に 5 問続けて送り、止まらないかを見る（要件 N2）
- 全候補に**同じ指示文・同じ質問**を使う。各質問を 3 回ずつ実行し、ぶれも見る
- 音声認識の聞き間違いを想定した質問（#27・#28）も入れる。音声認識そのものの比較は別の計画にする

## 3. 取り出す項目（JSON の形）
| 項目 | 内容 | 例 |
|---|---|---|
| `intent` | 質問の種類 | `damage` / `speed` / `type` / `stats` / `learnset` / `move_info` / `my_team` / `chat` / `clarify`（聞き返しが必要） |
| `attacker` / `defender` | ポケモン（英語名） | `Mimikyu` / `Garchomp` |
| `pokemon` | 単体の質問の対象 | `Gholdengo` |
| `move` | わざ（英語名） | `Play Rough` |
| `conditions` | 指定された条件 | 持ち物、特性、性格、努力値、ランク、天候、フィールド、メガシンカ、最速・最遅 など（側ごと） |
| `uses_context` | 直前の会話を使ったか | `true` / `false` |
| `missing` | 足りない情報 | `["defender"]` |
| `unknown_names` | 知らない名前 | `["アロロ"]` |

- 英語名への変換は、AI に任せる場合と、日本語のまま返させて対応表で変換する場合の 2 通りを試す（日本語名の扱いの方針に関わるため）

## 5. 評価の観点と合格ライン（案）
| 観点 | 測り方 | 合格ライン |
|---|---|---|
| 取り出しの正確さ | #1〜#20、#24〜#30 で、正解の要点が全部合っている割合 | 90% 以上 |
| 雑談の判別 | #21〜#23 を `chat` と判別できた割合 | 3 問とも |
| 聞き返しの正しさ | #24〜#26 で、勝手に補わず clarify にした割合 | 3 問とも |
| 数値の捏造がない | 取り出しの出力に、ダメージや種族値などの数値を AI が書いていない | 0 件 |
| 速さ | 送ってから返答が届くまで（取り出し） | 中央値 1.5 秒以内、遅い方の 5% でも 3 秒以内 |
| 連続の質問 | 1 分間に 5 問送る（3 回） | 上限エラー 0 件 |
| ぶれ | 同じ質問 3 回の結果が一致する割合 | 90% 以上 |
| 費用 | 1 問あたりの実際の使用量から計算 | 月 1,000 問で $10 以内 |
| データの扱い | 各社の規約で、入力が学習・改善に使われるか | 記録のみ（判断材料） |

## 6. 決め方
1. 合格ラインを満たす候補の中から、**取り出し用**は「上限の大きさ → 速さ → 正確さ」の順で選ぶ（第一候補は Gemma）
2. どれも満たさない場合は、指示文の改善 → ルールで即答する範囲の拡大 → Gemini Flash をクレジットで使う、の順で検討する
3. 予備（使えないときの切り替え先）を、別の会社から 1 つ決めておく

## 8. 実施に必要な準備（自分で行うこと）
- Google AI Studio で Gemini API キーを作る（無料）
- Groq のアカウントを作り、API キーを作る（無料）
- （#3 を試す場合）Google Cloud で Cloud Billing を設定し、Google Developer Program の画面で AI Pro のクレジットを有効化する。**予算アラートと 1 日の上限も設定する**
- キーはチャットやリポジトリに貼らない。実行環境の環境変数（またはクラウド環境のシークレット）に登録する
