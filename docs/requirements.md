# ロトムアシスト 目的と要件（v0.3 下書き）

- 状態: 下書き（未決事項なし）。合意できたら確定版 v1.0 にする
- 位置づけ: 再設計の出発点。既存の [design.md](design.md) は試作版（第1段階）の記録で、本書の内容とは食い違う部分がある
- 変更履歴: v0.1（チャットで提示）→ v0.2（入力方式・AIの選び方・費用方針を反映）→ v0.2.1（雑談は後回し、ニックネームは仮で「ロトム」、Claude Haiku は比較から外す）→ v0.3（速さの目標を確定、自分のパーティは 1 つ・6 体で後回し）

## 1. 目的
ポケモンチャンピオンズの対戦中や合間に、**ロトムをモチーフにした相棒に声で話しかけると、対戦に役立つ情報を声で返してくれる**アプリを作る。

## 2. 利用場面
| 場面 | ゲーム | アシスタントを開く端末 | 補足 |
|---|---|---|---|
| A | Switch 2 で対戦 | スマホのブラウザ | 主な使い方 |
| B | Switch 2 を PC でキャプチャ | 同じ PC のブラウザ | ゲーム音がマイクに入りうる |
| C | 対戦していないとき | どちらでも | 軽い雑談 |

- 対戦の種類: ランクマッチ、友人戦。**公式大会では使わない**
- 使う人: 基本は自分。将来、友人にも使ってもらう可能性がある

## 3. 機能要件

### 3.1 必須（最初に作る）
| ID | 機能 | 内容 |
|---|---|---|
| F1 | 声で質問・声で回答 | **ボタンを押して話す方式**を基本にする。回答は読み上げ（必須）＋画面に最低限の情報 |
| F2 | キャラクター | ロトムがモチーフ。語尾は「〜ロト」。呼び名は**仮で「ロトム」**（ニックネームは保留、候補は 7 章） |
| F3 | ダメージ計算 | ダメージ範囲と確定数。条件（持ち物・特性・性格・努力値・ランク・天候・フィールド・メガシンカなど）を指定できる |
| F4 | 素早さ比較 | 2 匹の比較、実数値。条件（スカーフ・ランク・最速など）を指定できる |
| F5 | 図鑑情報 | タイプ、弱点・耐性、種族値、覚える技、わざの情報 |
| F7 | 相手の型の扱い | 指定があれば従う。指定がなければ「よくある型」で計算し、**何を仮定したかを必ず言う** |
| F8 | 分からないとき | 分からないと言う。聞き返す（例: 「どっちが攻撃側ロト？」）。雑談を振られたら「雑談はまだ勉強中ロト」のように返す |

### 3.2 あると嬉しい（後から）
| ID | 機能 |
|---|---|
| L1 | 軽い雑談（対戦していないとき）。**後回しにする** |
| L0 | 自分のパーティ（**1 パーティ・6 体**）を登録し、技や努力値振りを答えられる。計算の「自分側」に自動で使える。**後回しにする**（旧 F6） |
| L2 | 合言葉で呼びかける常時待ち受け（ボタン式の上に追加するオプション） |
| L3 | 直前の会話を踏まえた質問（「じゃあハチマキなら？」） |
| L4 | キャラクターらしい声（PC では VOICEVOX など） |
| L5 | 画面の充実 |
| L6 | 友人の利用（利用者の区別、使いすぎ防止） |
| L7 | 音声のまま会話する AI（Gemini Live API）への発展 |

### 3.3 やらない（今回）
- 公式大会での利用
- ゲーム画面の自動認識（キャプチャ映像からの読み取り）
- 対戦の自動操作、相手の行動予測の断定

## 4. 非機能要件
| ID | 項目 | 目標（案） |
|---|---|---|
| N1 | 速さ | 話し終わってから読み上げ開始まで、よくある質問は 1 秒以内、AI を使う質問は 2〜3 秒以内 |
| N2 | 連続の質問 | 対戦中に 1 分間で 5 問続けても止まらない |
| N3 | 正確さ | 数値（ダメージ・種族値・実数値など）は必ずデータか計算ライブラリから出す。**AI に数値を作らせない** |
| N4 | 仮定の明示 | 仮定した条件（努力値・持ち物・型）を必ず言う |
| N5 | 費用 | **追加の契約・支払いなし**。今の Claude の契約と Google AI Pro の特典（毎月 $10 の Cloud クレジット）の範囲に収める |
| N6 | 端末 | スマホ（Android の Chrome を主、iPhone は可能な範囲）と PC のブラウザ |
| N7 | 秘密情報 | API キーはサーバ側の環境変数だけに置く。リポジトリ・ブラウザに出さない |
| N8 | 差し替えやすさ | 音声認識・AI・読み上げは、それぞれ差し替えられる作りにする（無料枠の条件変更に備える） |

## 5. 方式の方針（現時点の候補。比較テストで確定する）

### 5.1 処理の流れ
```
ボタンを押して話す
  → ① 音声認識
  → ② 理解: まずルールで解釈。できなければ AI で「質問の中身」を取り出す（AI は 1 回だけ）
  → ③ 計算・データ参照（@smogon/calc など）
  → ④ 回答文: テンプレートで作る（数値は AI を通さない。ロトムの口調もテンプレートで出す）
  → ⑤ 読み上げ
```

### 5.2 各段階の候補
| 段階 | 第一候補 | 予備・発展 |
|---|---|---|
| ① 音声認識 | Groq の Whisper（無料枠）。ポケモン名をヒントとして渡す | ブラウザの Web Speech API、Gemini に音声を直接渡す |
| ② 理解（取り出し） | ルール → **Gemma**（Gemini API 無料枠） | Gemini Flash（無料枠／AI Pro のクレジット）、Groq |
| ④ 回答文 | テンプレート（ロトム口調） | — |
| （後回し）雑談 | Gemini Flash（AI Pro のクレジット）を想定 | Gemini Flash 無料枠 |
| ⑤ 読み上げ | ブラウザの読み上げ | VOICEVOX（PC）、Gemini Live API |
| サーバ | Vercel の無料プラン | — |

AI の候補は [eval-plan.md](eval-plan.md) の比較テストで決める。

## 6. 制約・リスク
| ID | 内容 | 対応 |
|---|---|---|
| R1 | **チャンピオンズ用のデータ**（覚える技、仕様、使用率）が手に入るか未確認。今は Showdown の Gen9 データ | 早めに調査する。手に入らなければ「よくある型」を自分で登録する |
| R2 | 無料枠・特典の条件が予告なく変わる | N8（差し替えやすさ）で備える |
| R3 | 無料枠では入力が提供元の改善に使われうる | 個人情報を送らない。気になる部分は有料利用（クレジット）側に回す |
| R4 | ロトム自身の読み上げや、ゲーム音をマイクが拾う | ボタン式を基本にする。常時待ち受け（L2）では読み上げ中の認識を無視する |
| R5 | ポケモン名の聞き間違い | 音声認識へのヒント、近い名前への補正 |
| R6 | 公開 URL を他人が使うと無料枠・クレジットを消費する | 友人に使ってもらう段階で、パスコードや回数制限を入れる |
| R7 | クレジットを超えると請求が発生する（カード登録が必要） | Google Cloud の予算アラートと、API の 1 日の上限を設定する |
| R8 | 外部ツールの利用可否 | ランクマッチ・友人戦でもルールを確認する |

## 7. ニックネーム（保留）
当面は「ロトム」と呼ぶ。合言葉（L2）を作るときに決め直す。候補: **ダメロト**、**バトロト**、**ロトナビ**、ロトスケ、ピコロト、ロトリン、ロトッチ
- 呼びかけ例: 「バトロト、ガブリアスにミミッキュのじゃれつく」→「確定2発ロト！」
- 実機で聞き取りやすさを試して決める
