## 1. 全体像

```
┌──────────── ブラウザ（スマホ / PC）────────────┐
│ 画面: 大きな「押して話す」ボタン（PC はスペースキーも） │
│  ├ 録音（MediaRecorder）                              │
│  ├ 読み上げ（speechSynthesis）                         │
│  └ 状態表示・結果表示・診断                            │
└──────────────┬──────────────────────────┘
               │ POST /api/ask（音声 or 文字）
┌──────────────▼──── サーバ（Vercel / Next.js）────┐
│ ① 音声認識アダプタ ──→ Groq Whisper（無料枠）           │
│ ② 解釈: ルール解析 ──(失敗時)──→ AI 取り出しアダプタ   │
│        └ 名前の解決（日本語・あだ名・聞き間違いの補正）   │
│ ③ 処理: ダメ計 / 素早さ / 図鑑（@smogon/calc 第0世代＋アプリ用データ）│
│ ④ 回答文: テンプレート（ロトム口調）                     │
└──────────────┬──────────────────────────┘
               │ 返答（読み上げ文・画面表示用データ・診断情報）
               ▼
          ⑤ ブラウザで読み上げ

事前準備（手元で実行。アプリの外）
  データ作成スクリプト: Showdown 本体 ＋ PokeAPI ＋ 手入力の型 → アプリ用データ（JSON）
```

## 2. 技術の選択
| 項目 | 選択 | 理由 |
|---|---|---|
| アプリの枠組み | Next.js（App Router）＋ TypeScript | 画面とサーバ（API）を 1 つで作れる。試作版の資産を使える |
| ホスティング | Vercel 無料プラン | 無料、GitHub 連携で自動デプロイ、環境変数でキーを隠せる |
| 計算 | `@smogon/calc` の第0世代（チャンピオンズ） | 調査で対応を確認済み |
| 音声認識 | Groq Whisper（無料枠）。予備にブラウザの Web Speech API | ボタン式と相性が良い。ポケモン名のヒントを渡せる |
| AI | OpenAI 互換の形式で呼ぶ。**Gemini 3.5 Flash-Lite → 3.1 Flash-Lite → Groq gpt-oss-120b** の順（比較テストで決定、eval-plan.md 7 章） | 要件 N8（差し替えやすさ）。上限は 1 日 500 回（Flash-Lite）なので、別枠の予備を持つ |
| 読み上げ | ブラウザの speechSynthesis | 無料。将来 VOICEVOX（PC）や Gemini Live に差し替えられるように分けておく |
| データの保存 | なし（v1） | 雑談・パーティ・履歴は後回し。Supabase は後回し機能で使う |

## 3. 画面（ブラウザ）

### 3.1 状態
| 状態 | 表示 | 遷移 |
|---|---|---|
| 待機 | 「押して話すロト」 | ボタンを押す → 録音中 |
| 録音中 | 波形・経過秒 | 離す → 送信中（最長 10 秒で自動送信） |
| 考え中 | 「考え中ロト…」 | 返答 → 読み上げ中 |
| 読み上げ中 | 結果カード | 終わる → 待機。**ボタンを押すと読み上げを止めて録音開始** |
| エラー | 原因と対処 | ボタンで再試行 |

### 3.2 操作
- スマホ: 押している間だけ録音（押しっぱなし）。押しっぱなしが難しい場合に備え、「タップで開始／タップで終了」にも切り替えられるようにする
- PC: スペースキーを押している間だけ録音（キャプチャ画面と並べて使うため）
- マイクの許可は最初の 1 回だけ求める。画面が隠れたら録音・読み上げを止める
- 聞き取りが「終わった」の知らせ（onend）を返さずに止まることがある。以前は前の聞き取りが残っていると、押しても何もしなかった（2026-10-11 に実機で、6 回目以降に聞かなくなった）。今は、離して 4 秒以内に知らせが来なければ片付け、押したときに前のものが残っていれば捨ててやり直す。指が離れた知らせが来ない場合（pointercancel）も止める。押しっぱなしは 30 秒まで
- 聞き取りの経過（開始・音声の入り始め・話し始め・離した・終わり方・エラー、読み上げ、開いた端末）を roas.history に kind=event で送る（`/api/history`）。止まった原因を後から調べるため。質問の答えが 25 秒返らなければ打ち切る（「考え中」のままボタンが押せなくなるのを防ぐ）
- 色: ベースの色は #ff7a00。オレンジの上の文字は暗い色（白だと読みにくい）。攻撃側は赤、防御側は青
- 画面を開いたら、まず「このアプリは音が出ます。マナーモード（消音）を解除して、音量を上げてください」を出し、「音を鳴らしてはじめる」で合図の音を鳴らして確かめてもらう（ブラウザは操作の後でないと音を出せないため、この操作で音を使えるようにする）。「音なしで使う」も選べる
- 合図の音（`public/sounds/rotom.mp3`、約 1.7 秒）は「画面を開いたとき」と「答えの準備ができて読み上げる前」に鳴らす（その分答えは遅れるが、合図があった方がよい）
  - **音声認識の前後（聞き始め・聞き取り直後）では鳴らさない**。スマホでは音の再生が音声認識とぶつかり、聞き取りが途中で止まったり、次から聞かなくなったりした（2026-10-11 に実機で起きた）。マイクを使う前は、鳴っているときだけ止め、何も鳴っていなければ音の部品（audio 要素）に触らない（聞き始めの直前に audio 要素を片付ける操作をしただけで、スマホの聞き取りが止まった。ask_log #25）。画面の「答えの前の合図」で合図の音を入れたり切ったりできる（端末ごとに覚える）。聞き取りが止まる原因を切り分ける間は、初期値をオフにしている
  - 再生は 1 つの audio 要素を使い回し、鳴らし終わったら中身を外す。最初の「音を鳴らしてはじめる」で、合図の音と読み上げの両方を使える状態にする（スマホは最初の読み上げも操作の後でないと出ないため。以前は「もう一度読む」を押すまで読み上げなかった）
  - 聞き始めの合図は、ボタンの色と振動（対応している端末だけ）
- 声: 「ブラウザ」（speechSynthesis。速い）と「Gemini」（`/api/tts` → Gemini の音声生成 `gemini-3.8-flash-lite-tts`、声は Puck。自然だが約 2 秒かかる）を選べる。選んだ声は端末に覚える。Gemini は合図の音を鳴らしている間に用意を始める。無料枠の上限・失敗のときはブラウザの読み上げに戻す

### 3.3 表示
- 結果カード: 質問の解釈（「ミミッキュのじゃれつく → ガブリアス」）、結果（ダメージ範囲・確定数など）、**仮定した条件**
- 診断（折りたたみ）: 各段階の所要時間、使った AI、聞き取った文字。反応が悪いときの切り分け用
- 文字入力欄（折りたたみ）: 音声が使えないときや、テスト用

## 4. サーバ

### 4.1 API
| API | 入力 | 出力 | 用途 |
|---|---|---|---|
| `POST /api/ask` | 音声（短いファイル）または文字、直前の質問（任意） | 読み上げ文、画面用データ、仮定、診断情報 | 本番の 1 往復。往復を 1 回にして速くする |

- 1 往復で ①〜④ を済ませる（ブラウザとサーバの往復を減らすため）
- 文字だけでも受け付ける（テスト・文字入力用）

### 4.2 処理の流れ
1. **音声認識**: Groq Whisper にポケモン名・わざ名のヒントを付けて送る。失敗したら「聞き取れなかったロト」と返す（ブラウザ側の Web Speech API に切り替える選択肢も出す）
2. **ルール解析**: よくある型の質問を、決まったパターンで解釈する（例: 「AにBのC」「Aの素早さ」「Aのタイプ」）
3. **AI 取り出し**: ルールで解釈できなかったときだけ。質問の中身を JSON で返させる（6 章の形）。AI には数値を作らせない
4. **名前の解決**: 取り出した名前を、アプリ用データの ID に変える（7 章）
5. **確認**: 足りない情報・知らない名前があれば、聞き返す返答を作る
6. **処理**: 種類ごとの処理（8 章）
7. **回答文**: テンプレートでロトム口調の短い文を作る（9 章）

### 4.3 AI の呼び出し（アダプタ）
- OpenAI 互換の形式（Chat Completions）で統一する
- 設定（環境変数）: `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`。予備用に `LLM_FALLBACK_*`
- 上限エラー（429）や時間切れ（2 秒）のときは予備に切り替える。予備も駄目なら「混み合ってるロト」と返す
- 音声認識も同じ考え方: `STT_BASE_URL`、`STT_API_KEY`、`STT_MODEL`

## 5. 速さの予算（要件 N1）
| 段階 | ルールで解釈できる場合 | AI を使う場合 |
|---|---|---|
| 録音の送信 | 0.1〜0.3 秒 | 同左 |
| 音声認識（Groq Whisper） | 0.3〜0.8 秒 | 同左 |
| ルール解析・名前の解決 | 0.05 秒未満 | 同左 |
| AI 取り出し | — | 0.5〜1.5 秒 |
| 計算・回答文 | 0.05 秒未満 | 同左 |
| 読み上げ開始 | 0.1〜0.3 秒 | 同左 |
| **合計** | **約 1 秒**（目標 1 秒以内） | **約 2〜3 秒**（目標 2〜3 秒以内） |

- Vercel の関数が眠っていると、最初の 1 回だけ数百ミリ秒〜1 秒ほど遅くなる（コールドスタート）
- 診断に各段階の時間を出し、実測で見直す

## 6. 質問の中身の形（解釈の結果）
ルール解析と AI 取り出しは、同じ形を返す（[eval-plan.md](eval-plan.md) 3 章と同じ）。

| 項目 | 内容 |
|---|---|
| `intent` | `damage` / `speed` / `type` / `stats` / `learnset` / `move_info` / `my_team`（後回し）/ `chat`（後回し）/ `clarify` |
| `attacker`・`defender` | ダメ計の攻撃側・防御側（名前と条件） |
| `pokemon`・`pokemon2` | 単体・2 匹比較の対象（名前と条件） |
| `move` | わざ |
| 条件（側ごと） | 持ち物、特性、性格、SP（0〜32。「252振り」は 32、「極振り」は 32 とみなす）、ランク、メガシンカ、テラスタルは無し（チャンピオンズにないため扱わない）、最速・最遅 |
| 場の条件 | 天候、フィールド、壁（リフレクター・ひかりのかべ）、急所 |
| `missing` | 足りない情報 |
| `unknown_names` | 解決できなかった名前 |

- 名前は**日本語のまま**返させ、名前の解決はサーバ側で行う（決定 A5。日本語名は対応表から読む方針のため。AI の英語変換の誤りを避ける）
- **名前の補正も AI にさせない**（決定 A6）。知らない名前・聞き間違いは、聞こえたままのカタカナで返させ、7 章のあいまい一致で直す。AI に直させると「さあ内藤」→ニンフィア、「アロロ」→アローラキュウコンのように、別の実在のポケモンに置き換えてしまうため（eval-plan.md 7.8）

## 7. 名前の解決
1. 正規化: 全角・半角をそろえる、ひらがなとカタカナをそろえる、空白・記号を除く
2. 完全一致: 日本語名・英語名
3. 別名: あだ名・略称（例: ガブ、ミミ、メガリザY）、よくある聞き間違い（運用しながら追加）
4. あいまい一致: 読み（カナ）の近さで候補を探す。**1 つに絞れたら採用し、読み上げでは直したことを言わない**（毎回言うとうるさいため）。見出しは直した名前で出し、画面の詳しい結果に「「ミミック」はミミッキュとして計算した」と出す。複数なら聞き返す
   - 文字（カナ）の違いと、**読み（ローマ字に近い形）の違い**の小さい方で比べる。読みでは小さい字を前の音に付け（キュ → kyu）、促音・伸ばす音を落とし、オウ/オー・エイ/エーをそろえる。例: ミミック（mimiku）→ミミッキュ（mimikyu）、エースバン→エースバーン、カイリュウ→カイリュー
   - 音声認識が名前の一部を漢字で書いたとき（サーフ号、月光蛾）は、`data/readings.json` の読みに置き換えてから比べる（ask_log で見つけたら足す）
   - 4 文字以上のあだ名も比べる対象にする
   - ルール解析でも、辞書で読めない語に当たったら、その位置の 3〜10 文字をポケモン・わざの聞き間違いとして照合する。辞書の短いあだ名で切って行き詰まったとき（ミミック を「ミミ」+「ック」）は手前に戻って切り直す。直した名前は聞こえた形のまま渡す
5. チャンピオンズにいない（ハバタクカミ、こだわりハチマキなど）: 「〇〇はチャンピオンズにいないロト」。そのため、チャンピオンズにいない名前の一覧も持つ
6. 見つからない: 「〇〇は分からないロト」

## 8. 種類ごとの処理
| intent | 処理 | 使うデータ |
|---|---|---|
| `damage` | `@smogon/calc` 第0世代で計算。範囲・割合・確定数（乱数の全範囲で判定） | 計算ライブラリ |
| `speed` | 両者の実数値を計算し、ランク・スカーフ・天候の特性などを反映して比べる。同速も言う | 計算ライブラリ |
| `type` | タイプと、弱点（4倍・2倍）・半減・無効 | アプリ用データ（タイプ相性表） |
| `stats` | 種族値（6 つと合計） | 同上 |
| `learnset` | 覚えるか（はい／いいえ） | 同上（Showdown の覚える技） |
| `move_info` | タイプ、分類、威力、命中、優先度 | 同上 |
| `clarify` | 何が足りないか・どれと迷ったかを聞き返す | — |
| `my_team` / `chat` | 「まだ勉強中ロト」と返す（後回し） | — |

### 8.1 相手の型の扱い（要件 F7）
1. 質問で指定された条件を最優先
2. 指定がなければ、**幅で答える**: 最小（SP0・補正なし）〜最大（SP32・補正あり）の 2 通りを計算し、「相手の振り方で〇〜〇%ロト」と言う
3. 「よくある型」（`sets.json`）は**保留**（A4）。登録できたら、2 の前に「よくある型」を使い、使った型を必ず言う形に拡張する（データの形は 10 章のまま残す）
4. 自分側（攻撃側が自分のとき）の条件も、指定がなければ同じ扱い。自分のパーティ機能（後回し）ができたら、登録内容を使う

## 9. 回答文（テンプレート）
- 最初に結論、次に数値、最後に仮定。1〜2 文
- 例
  - ダメ計: 「確定2発ロト！ 53から63パーセント。相手は無振りで計算したロト」
  - 乱数: 「乱数1発ロト。倒せるのは37パーセントくらいロト」
  - 素早さ: 「ガブリアスの方が速いロト！ 169対134ロト」
  - 聞き返し: 「どっちが攻撃するロト？」
  - 分からない名前: 「アロロは分からないロト」
- 同じ意味の言い回しを数通り用意し、ランダムに選ぶ（単調にならないように）
- 数値は読み上げやすく丸める（画面には正確な値を出す）

## 10. アプリ用データ（事前に作る）
| ファイル | 中身 | 元データ |
|---|---|---|
| `species.json` | ID、英語名、日本語名、タイプ、種族値、特性、メガ・フォルム | `@smogon/calc` 第0世代、Showdown 本体、PokeAPI |
| `moves.json` | ID、英語名、日本語名、タイプ、分類、威力、命中、優先度 | 同上 |
| `items.json`・`abilities.json` | ID、英語名、日本語名 | 同上 |
| `learnsets.json` | ポケモンごとの覚える技 | Showdown 本体 `data/mods/champions/learnsets.ts` |
| `aliases.json` | あだ名・略称・聞き間違い → ID | 手入力（運用で追加） |
| `readings.json` | 音声認識が書く漢字 → 読み（サーフ号、月光蛾） | 手入力（運用で追加） |
| `sets.json` | よくある型（持ち物・特性・性格・SP・わざ） | **保留**（A4）。v1 では作らない。作るときは出典・シーズン・取得日を記録し、自動で定期取得はしない |
| `whisper-hints.txt` | 音声認識に渡すヒント（よく使う名前） | 上から自動で作る |

- データ作成スクリプトは手元で実行し、結果の JSON をリポジトリに入れる（アプリ実行時に外部からデータを取りに行かない＝速くて安定）
- シーズンやバージョンの更新時に作り直す。出典（Showdown、PokeAPI）を画面と README に書く

## 11. 安全・運用
| 項目 | 方針 |
|---|---|
| API キー | Vercel の環境変数だけに置く。ブラウザに出さない |
| 他人の利用 | 公開 URL を知られると無料枠を消費されるリスクがある。**パスコードは当面付けない**（A1）。URL を人に教えない運用にし、友人に使ってもらう段階（要件 L6）で付ける |
| 回数制限 | サーバ側で 1 分あたりの回数に上限を付ける（無料枠を守る） |
| 音声の扱い | 音声はその場で文字にして捨てる。保存しない |
| 外部サービスへのデータ | 無料枠では入力が改善に使われうる（要件 R3）。送るのは質問の音声・文字だけ |

## 12. 試作版のコードの扱い

| 入力検証（`lib/validate.ts`）、API のテスト | 考え方を**使う** |

| 常時の音声認識（`app/useVoiceAssistant.ts`）、合言葉（`lib/wakeword.ts`） | v1 では使わない。合言葉の機能（後回し L2）で再利用を検討 |
| 小さい対応表（`data/ja-en.json`） | アプリ用データに**置き換える** |
| Supabase の履歴（`/api/history`、`supabase/`） | v1 では使わない（後回し機能で再検討） |
| Claude API 版（`cli/`） | 使わない（要件 Q5） |

## 13. テストの方針
- 単体テスト: ルール解析、名前の解決、各処理、回答文
- 計算の基準テスト: Showdown の計算機（Champions モード）で確認した値と比べる数ケース
- 比較テストの 30 問を、解釈の回帰テストとして使い続ける
