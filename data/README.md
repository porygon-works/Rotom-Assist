# data/ — 辞書と、聞き間違い・言い回しのヒント

質問の記録（`roas.ask_log`）を見直して足していくヒントは、**種類ごとに置き場所が 1 つ**に決まっている。迷ったら上の表から順に当てはまるものを選ぶ。

## どこに足すか

| こういうとき | 足す場所 | 例 | 効く範囲 |
|---|---|---|---|
| 質問文の一部が**別の言葉**に書き起こされた（助詞や前後で判断が要る、名前以外の語、複数の語にまたがる） | `misheard.json` | 受診→じしん、HBブリ→HB振り、加工補正→下降補正、偉大党→イダイトウ | 質問文の全体。ルールも AI も直した文で読む |
| ポケモン・わざ・持ち物・特性の**あだ名・略称・漢字表記**（それだけで名前と決まる語） | `aliases.json` | ガブ、ハチマキ、地震、変幻自在、サーフ号 | 名前の解決（ルールの辞書・AI が返した名前の両方） |
| 音声認識が名前の**一部を漢字**で書く（読みに直せば近い名前に当たる） | `readings.json` | 号→ゴウ、月光→ゲッコウ、思念→シネン | 読みの近さで名前を当てるとき（`lib/resolve.ts`） |
| 意味は分かっていて**読み飛ばしてよい**言い回し（質問の聞き方・つなぎの言葉） | `rule-words.json` | どれぐらい、耐えますか、打ったら、に対して | ルール解析だけ（AI は自分で読む） |
| 振り方・性格補正・ランク・残り HP など**値を持つ**言い方 | `lib/rules.ts` の `pattern()` | HB特化、C下降補正、S+2、HP半分、威力150 | ルール解析だけ |

迷いやすいところ:

- 名前そのものの聞き間違いでも、**前後の文字がないと決められない**もの（「走れるの」= アシレーヌ、「目がグソクムシ」= メガグソクムシャ）は `misheard.json`。それだけで名前と決まるもの（「サーフ号」）は `aliases.json`
- `rule-words.json` に**条件の意味がある語を入れない**（「ハチマキ」「晴れ」などを入れると、ルールが黙って捨てる）
- 名前の補正を AI にさせない（構成設計 A6）。AI の指示文（`lib/extractPrompt.ts`）は最後の手段

## 書き方

### `misheard.json`

```json
{ "from": "(ガム|株)(?=の|に|が|は|って|で)", "to": "ガブ", "log": [50, 156], "note": "任意", "examples": [["特化株の受信", "特化ガブのじしん"]] }
```

- 節（`sections`）の順、節の中の上から順に当てる。前の行の結果を前提にする行（「目が」→メガ は グソクムシャの行の後）は `note` に書く
- `from` は正規表現。質問文は**直す前**（ひらがな・カタカナ・漢字のまま、全角英字はそのまま）なので、かなの揺れは `[しシ]` のように両方書く
- `log` は見つけた ask_log の id。`examples` は [聞こえた文, 全部の行を当てた後の文]。`test/misheard.test.ts` が全件を確かめ、**2 回当てても変わらない**ことも確かめる（ルール解析は直した文をもう一度直すため）
- 名前の直前・助詞の前など、効く場所を先読み（`(?=の|に|…)`）で絞る。短い語ほど誤爆しやすい

### `aliases.json` / `readings.json`

- `aliases.json` の値は `names.json` の正式名（日本語）。種類ごと（pokemon・moves・items・abilities・weather・terrain）に分かれている
- `readings.json` は長いものから先に置き換わる。1 字の読みは誤爆しやすいので、実際の記録で見つけたものだけ足す

### `rule-words.json`

- 組（`groups`）は人が読むための分け方で、動きは同じ。ひらがなとカタカナは同じに扱うので、片方だけ書けばよい
- 足したら `npx tsx eval/rules.ts` で**即答の誤り 0 件**を確かめる
